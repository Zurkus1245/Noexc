# 11. Функциональные требования: кабинет клиента (мобильное приложение)

Статус: draft · Дата: 2026-11-23 · Продукт: NoExcuse, MVP, рынок ЕС
Основа: `00-validation.md` (O1–O8 по рекомендациям), `NoExcuse_MVP_Plan.md` v1.1 (§2.2, §5), `CLAUDE.md` (§5, §6, §8, §9), `01-conventions.md`, `12-fr-shared-admin.md` (серверная часть), `13-business-rules.md` (каталог BR), `20-screen-map.md` (экраны SCR-S, SCR-C), исходное ТЗ «Новое ТЗ» (§4.2 путь подопечного).

Область: только кабинет клиента. Тренерский кабинет, админка и серверные правила (FR-AUTH, FR-LINK-001…012, FR-ACCT-001…006, FR-NOTIF-001…004) описаны в других файлах; здесь — поведение экрана клиента и ссылки на них.

## 0. Соглашения

- **ID:** `FR-<MOD>-1NN`. Клиентский диапазон начинается со 100, чтобы не пересекаться с файлом тренера. Модули: LINK, CAL, WORK, NUT, PROG, NOTIF, ACCT.
- **Приоритет:** Must / Should / Later. Later = вне MVP (зафиксировано для бэклога). Тип Could/Won't из `01-conventions.md` здесь не используется.
- **Этап EPIC:** EPIC-1 = этап 1 плана (связь тренер–клиент); EPIC-2 = этап 2 (план и календарь); EPIC-3 = этап 3 (факт и питание); EPIC-4 = этап 4 (готовность к бете); EPIC-5 = этап 6 (остальной MVP); EPIC-6 = этап 7 (публичный запуск). Этап 5 (закрытая бета) новых клиентских требований не добавляет.
- **[O#]:** требование зависит от решения владельца. Значение взято из рекомендации `00-validation.md` и записано в `13-business-rules.md`. Другое решение меняет одно правило.
- **Экран:** название словами; в скобках ID из `20-screen-map.md`.
- **Тексты** в требованиях — рабочие формулировки на русском. Финальные тексты — после решения O7 и дизайн-ревью.
- **Время и даты:** UTC ISO-8601; дата тренировки `YYYY-MM-DD` в часовом поясе клиента; ID операций — UUID, создаётся на клиенте.
- **Ошибки:** клиент ветвит логику только по `code` из RFC 9457 problem+json. Реестр кодов — раздел 2.

## 1. Бизнес-правила (BR), на которые ссылаются требования

Определения взяты из `13-business-rules.md`. Здесь — краткий смысл для клиента.

| ID | Смысл для клиента |

| BR-LINK-001 | Связь создаётся только погашением валидного инвайта; один инвайт — не более одной связи |
| BR-LINK-002 | У клиента не более одной связи в статусе active или paused [O2] |
| BR-LINK-003 | Тренер видит данные клиента только при связи, статусе не ended и действующих согласиях (`coach_access`, для здоровья — `health_data`) |
| BR-LINK-004 | Неизвестный статус связи трактуется как закрытый доступ (fail-closed): клиент показывает «связь недоступна» |

| BR-LINK-006 | Переходы: pause и resume — тренер; end — тренер, клиент или администратор |
| BR-LINK-007 | Отвязка закрывает доступ тренера немедленно (следующий запрос тренера получает 404) |

| BR-LINK-011 | При удалении тренера связь переходит в ended без имени тренера; клиент сохраняет историю |
| BR-INVITE-001 | Код инвайта: не менее 128 бит, 26 символов Crockford base32 |
| BR-INVITE-003 | Срок инвайта — 168 часов от создания |
| BR-INVITE-004 | Инвайт одноразовый |
| BR-INVITE-006 | Любое негативное состояние инвайта — один ответ 404 `INVITE_INVALID` с идентичным телом |

| BR-CONSENT-001 | Обязательные согласия для связи: `tos`, `health_data`, `coach_access`; `marketing` необязательно и выключено по умолчанию |

| BR-CONSENT-003 | Согласие действует только для текущей версии текста |

## 2. Коды ошибок и тексты для клиента

Коды из `12-fr-shared-admin.md` и `13-business-rules.md` повторно используются. Новые коды помечены «новый»: их нужно добавить в реестр `packages/contracts`.

| Код | HTTP | Когда | Текст клиенту |
|---|---|---|---|
| `UNAUTHENTICATED` | 401 | Сессия истекла после одной попытки refresh | «Войдите снова» (S19) |
| `VALIDATION_FAILED` | 422 | Формат или диапазон значения | Текст под полем |
| `NOT_FOUND` | 404 | Чужой или закрытый ресурс, отсутствующая запись | «Не найдено или недоступно» (S16) |
| `INVITE_INVALID` | 404 | Истёкший, использованный, отозванный, несуществующий или чужой код (BR-INVITE-006) | «Код недействителен. Попросите тренера выслать новый» (C03) |
| `RATE_LIMITED` | 429 | Превышены попытки ввода кода (BR-INVITE-009) или лимит запросов экспорта | «Слишком много попыток. Попробуйте позже» |
| `CONSENT_REQUIRED` | 422 | Нет обязательного согласия или согласие не текущей версии | Экран согласий (S07) или переподтверждения (S09) |
| `FORBIDDEN_ROLE` | 403 | Возраст младше 18 лет (FR-ACCT-005) | «Сервис доступен с 18 лет» (S21) |
| `LINK_EXISTS` | 409 | У клиента уже есть связь active или paused (FR-LINK-007) | «У вас уже есть тренер. Сначала завершите текущую связь» |
| `INVALID_TRANSITION` | 409 | Действие не допускается в текущем статусе (повторная пауза, связь ended) | Текст зависит от экрана |
| `VERSION_CONFLICT` | 409 | Параллельное изменение данных | «Данные обновились. Повторите» |
| `LINK_BLOCKED` | 403 | Связь заблокирована администратором (новый, уточнить с FR-ADM-004) | «Связь с тренером сейчас недоступна. Если это ошибка, напишите в поддержку» (C32) |
| `RESCHEDULE_NOT_ALLOWED` | 422 | Перенос вне правил тренера (новый) | «Нельзя перенести: правила тренера» |
| `INTERNAL` | 500 | Сбой на сервере | «Что-то пошло не так. Повторите» + requestId (S18) |
| `NETWORK_OFFLINE` | клиент | Нет сети (клиентский код, не из API) | «Нет соединения. Действие не выполнено» (S17) |
| `NETWORK_TIMEOUT` | клиент | Нет ответа 15 с (клиентский код) | «Не отправлено» + «Повторить» |
| `PUSH_PERMISSION_DENIED` | клиент | Отказ в системном разрешении на push | «Уведомления выключены в настройках телефона» (S12) |

Сквозные правила состояний для всех экранов клиента:
- **Загрузка:** скелетон, без пустого экрана.
- **Пусто:** текст без давления и одно действие (или «нет действия»).
- **Офлайн:** «Нет соединения» (S17). Факт, отметки и итоги из кэша не показываются. Последняя полученная версия плана показывается только для чтения с меткой «Нет связи, версия N» (допущение, раздел 5).
- **Ошибка сервера:** текст, «Повторить», requestId (S18). Ответ 5xx никогда не показывается как успех.
- **Доступ закрыт** (`NOT_FOUND`, `LINK_BLOCKED`, связь ended или неизвестный статус по BR-LINK-004): нейтральный текст без причины.
- **401:** одна попытка refresh; при неудаче — выход и экран входа (S19).

## 3. Требования

### 3.1. LINK: вход по инвайту, согласия, пауза, отвязка

### FR-LINK-101 Установка без инвайта: экран ввода кода тренера
- **Актор:** клиент (новый пользователь).
- **Приоритет:** Must. **Этап:** EPIC-1.
- **Предусловия:** приложение установлено, сессии нет.
- **Описание:** единственный вход нового клиента — экран ввода кода тренера. Самостоятельной регистрации и выбора роли «пользователь» нет: самостоятельные пользователи вне MVP, один аккаунт — одна роль [O1].
- **Критерии приёмки:**
  - Позитивный: Дано: приложение открыто впервые без сессии. Когда: экран загрузился. Тогда: показано поле «Код тренера» и подсказка «Нет кода? Попросите тренера его выслать»; кнопка «Продолжить» неактивна, пока поле пусто.
  - Негативный: Дано: экран ввода кода открыт. Когда: пользователь ищет путь к регистрации без кода. Тогда: такого пути нет, переход на экран входа без кода недоступен.
- **Ошибки:** `NETWORK_OFFLINE`.
- **Экран:** «Введите код тренера» (C02).
- **Связи:** BR-LINK-001, BR-INVITE-001, [O1].

### FR-LINK-102 Ввод кода вручную
- **Актор:** клиент (без сессии).
- **Приоритет:** Must. **Этап:** EPIC-1.
- **Предусловия:** открыт экран ввода кода; код получен от тренера.
- **Описание:** код 26 символов Crockford base32, вводится группами по 4 символа. Пробелы, дефисы и регистр игнорируются; вставка из буфера допустима. Буквы I, L нормализуются в 1, O — в 0. Перед запросом проверяется длина. Проверка на сервере выполняется по нажатию «Продолжить».
- **Критерии приёмки:**
  - Позитивный: Дано: поле пусто. Когда: вставлена строка «ABCD-EFGH-JKMN-PQRS-TVWX-YZ23» (26 символов без учёта разделителей) и нажато «Продолжить». Тогда: код принят, открыт экран проверки возраста (FR-LINK-107).
  - Негативный: Дано: введено 25 символов. Когда: нажато «Продолжить». Тогда: под полем «Проверьте код: 26 символов», запрос на сервер не отправляется.
- **Ошибки:** `VALIDATION_FAILED` (клиентская проверка), `INVITE_INVALID` (см. FR-LINK-104), `NETWORK_OFFLINE`.
- **Экран:** «Введите код тренера» (C02).
- **Связи:** BR-INVITE-001, BR-INVITE-006.

### FR-LINK-103 Вход по ссылке-приглашению
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-1.
- **Предусловия:** приложение установлено; ссылка содержит код во фрагменте (`/join#код`).
- **Описание:** при открытии ссылки приложение сразу открывает экран «Подключение к тренеру» с кодом из фрагмента, минуя ручной ввод. Фрагмент URL не отправляется на сервер в составе запроса страницы и не попадает в логи. Код не сохраняется в хранилище устройства до погашения.
- **Критерии приёмки:**
  - Позитивный: Дано: приложение установлено, ссылка открыта. Когда: приложение получило ссылку. Тогда: открыт экран «Подключение к тренеру» (C01) с проверкой кода; поле ручного ввода не показано.
  - Негативный: Дано: приложение не установлено. Когда: ссылка открыта в браузере. Тогда: страница-посадка (веб, вне приложения, допущение) показывает ссылку на магазин и текст «Откройте приложение и введите код тренера». Код не отображается в адресной строке после перехода.
- **Ошибки:** `INVITE_INVALID`, `NETWORK_OFFLINE`.
- **Экран:** «Подключение к тренеру» (C01).
- **Связи:** BR-INVITE-001, BR-INVITE-006.

### FR-LINK-104 Негативные состояния инвайта: один нейтральный текст
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-1.
- **Предусловия:** клиент ввёл код или открыл ссылку.
- **Описание:** истёкший, использованный, отозванный, несуществующий и чужой код дают один и тот же ответ `INVITE_INVALID` (404). Экран показывает один текст без причины. Нельзя различать состояния по тексту, статусу или времени ответа.
- **Критерии приёмки:**
  - Позитивный: Дано: код истёк. Когда: клиент проверяет код. Тогда: показано «Код недействителен. Попросите тренера выслать новый» (C03); кнопка «Ввести другой код» ведёт на ввод кода.
  - Негативный: Дано: код отозван тренером. Когда: клиент вводит его. Тогда: текст и статус ответа совпадают с ответом для истёкшего кода (тестом сравниваются тело и статус); слово «отозван» в интерфейсе не появляется.
- **Ошибки:** `INVITE_INVALID` (404).
- **Экран:** «Код недействителен» (C03).
- **Связи:** BR-INVITE-006, BR-INVITE-004, BR-INVITE-005. Серверная часть: FR-LINK-004.

### FR-LINK-105 Ограничение попыток ввода кода
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-1.
- **Предусловия:** клиент вводит код.
- **Описание:** сервер допускает не более 5 попыток за 10 минут отдельно по IP и по значению кода. Превышение даёт 429 даже при верном коде. Экран показывает обратный отсчёт по `Retry-After` и не раскрывает, верен ли код.
- **Критерии приёмки:**
  - Позитивный: Дано: пять попыток подряд за 10 минут. Когда: шестая попытка. Тогда: код не проверяется, кнопка «Продолжить» неактивна, показано «Слишком много попыток. Попробуйте через 10:00» с обратным отсчётом до нуля.
  - Негативный: Дано: четыре неверные попытки. Когда: пятая попытка с верным кодом. Тогда: код принят, блокировка не срабатывает.
- **Ошибки:** `RATE_LIMITED` (429), `NETWORK_OFFLINE`.
- **Экран:** «Введите код тренера» (C02).
- **Связи:** BR-INVITE-009.

### FR-LINK-106 Погашение инвайта и создание связи
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-1.
- **Предусловия:** код действителен (FR-LINK-104 не сработал); клиент подтвердил возраст (FR-LINK-107).
- **Описание:** порядок шагов: код → возраст → вход через провайдера (Sign in with Apple обязателен при социальном входе) → обязательные согласия (FR-LINK-108…110) → подтверждение связи (C05) → атомарное погашение инвайта и создание связи (C06). - **Описание:** смена тренера выполняется в два шага. Сначала клиент отвязывается от текущего тренера (FR-LINK-119), затем вводит новый код (FR-LINK-102 или FR-LINK-103) и проходит согласия заново для нового тренера. Замены «одним шагом» нет: пока есть открытая связь, ввод кода другого тренера отклоняется. Новая связь — отдельная запись; согласия и история старой связи не переходят (BR-LINK-008).
- **Критерии приёмки:**
  - Позитивный: Дано: связь с тренером X завершена, клиент ввёл действующий код тренера Y и дал согласия. Когда: сервер создал связь. Тогда: связь с Y active, данные X недоступны для Y.
  - Негативный: Дано: связь с тренером X active. Когда: клиент вводит действующий код тренера Y. Тогда: ответ `LINK_EXISTS` (409), текст «У вас уже есть тренер. Сначала завершите текущую связь», кнопка «Перейти к отвязке» ведёт на FR-LINK-119; связь с X сохраняется.
- **Ошибки:** `LINK_EXISTS` (409), `INVITE_INVALID`, `CONSENT_REQUIRED`, `NETWORK_OFFLINE`.
- **Экран:** «Сменить тренера» (C28); «Подключение к тренеру» (C01).
- **Связи:** BR-LINK-001, BR-LINK-002, BR-LINK-008, BR-INVITE-004. Серверная часть: FR-LINK-007.

### FR-LINK-121 Связь закрыта тренером, администратором или удалением тренера
- **Актор:** клиент, система.
- **Приоритет:** Must. **Этап:** EPIC-1 (отображение); блокировка администратором — EPIC-4 (Admin-lite к бете) [O4].
- **Предусловия:** связь переведена в ended или заблокирована.
- **Описание:** если связь закрыта тренером, администратором или удалением тренера, экран «Сегодня» и календарь показывают «Связь с тренером недоступна» без причины. При блокировке администратором текст: «Связь с тренером сейчас недоступна. Если это ошибка, напишите в поддержку». При удалении тренера имя не показывается. Собственные данные, экспорт и удаление аккаунта доступны. Неизвестный статус связи обрабатывается как закрытый (BR-LINK-004).
- **Критерии приёмки:**
  - Позитивный: Дано: администратор заблокировал связь. Когда: клиент обновляет «Сегодня». Тогда: показан текст блокировки (C32), тренировки тренера не показаны, открыты «Мои данные» и «Профиль».
  - Негативный: Дано: клиент выполняет тренировку, связь заблокирована в этот момент. Когда: клиент нажимает «Завершить». Тогда: сервер отвечает `LINK_BLOCKED` (403); тренировка показана как «Не сохранено», не «Сохранено»; данные не отправлены.
- **Ошибки:** `LINK_BLOCKED` (403), `NOT_FOUND`, `INTERNAL`.
- **Экран:** «Связь недоступна» (C32); «Сегодня» (C07).
- **Связи:** BR-LINK-004, BR-LINK-006, BR-LINK-011, BR-SYNC-002, BR-SYNC-004. Серверная часть: FR-ADM-004, FR-ADM-011.

### FR-LINK-122 Дисклеймер при первом открытии плана

  - Негативный: Дано: тренер выпустил версию 4, сети нет. Когда: клиент открывает «Сегодня». Тогда: показана версия 3 с меткой «Нет связи, версия 3»; версия 4 не показана как актуальная.

### FR-CAL-103 Пустое состояние: тренер ещё не назначил план

- **Критерии приёмки:**
  - Позитивный: Дано: связь active, план не назначен. Когда: открыт «Сегодня». Тогда: текст «Тренер ещё готовит план» без ошибки; кнопки «Начать» нет.
  - Негативный: Дано: связи нет (отвязка). Когда: открыт «Сегодня». Тогда: показан экран «Тренер не назначен» (C04), а не текст про план; кнопки «Начать» нет.
- **Ошибки:** `NETWORK_OFFLINE`.
- **Экран:** «Сегодня» (C09); «Календарь» (C15); «Тренер не назначен» (C04).
- **Связи:** BR-LINK-001.

### FR-CAL-104 День отдыха

  - Негативный: Дано: на сегодня нет тренировки. Когда: клиент ищет кнопку «Пропустить». Тогда: кнопки нет, отметка пропуска не создаётся.

### FR-CAL-105 Календарь: неделя и месяц
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-2.
- **Предусловия:** связь active.
- **Описание:** календарь показывает неделю (по умолчанию) или месяц. Каждый день имеет статус с текстом, а не только цветом: «Запланировано», «Выполнено», «Пропуск», «Пауза», «Отдых», «Перенесено». Запрос идёт за диапазон `from/to`; диапазон больше 42 дней клиент не запрашивает.
- **Критерии приёмки:**
  - Позитивный: Дано: за неделю есть 3 запланированные и 2 выполненные тренировки. Когда: открыт «Календарь». Тогда: каждый день показан текстом статуса; дни «Выполнено» отличаются текстом, не только цветом.
  - Негативный: Дано: выбран месяц, сеть недоступна. Когда: открыт календарь. Тогда: показан экран ошибки «Нет соединения. Календарь не обновлён» (S17) без данных.
- **Ошибки:** `VALIDATION_FAILED` (диапазон больше 42 дней), `NETWORK_OFFLINE`, `NETWORK_TIMEOUT`, `INTERNAL`.
- **Экран:** «Календарь» (C15).
- **Связи:** BR-DATE-001, BR-SYNC-001.

### FR-CAL-106 Пропуск тренировки
- **Актор:** система, клиент (просмотр).
- **Приоритет:** Must. **Этап:** EPIC-2.
- **Предусловия:** на дату назначена тренировка; связь active или paused.
- **Описание:** статус «Пропуск» появляется, когда день клиента закончился, а факта нет. Статус вычисляется сервером по часовому поясу клиента. Пропуск не появляется за день, который ещё не закончился, и в дни паузы.
- **Критерии приёмки:**
  - Позитивный: Дано: тренировка на 2026-12-01 не выполнена, клиент в `Europe/Berlin`. Когда: наступило 00:00 2026-12-02 по Берлину. Тогда: в календаре 2026-12-01 показан «Пропуск».
  - Негативный: Дано: тренировка выполнена в 23:50 дня. Когда: наступает следующий день. Тогда: статус «Выполнено», пропуска нет. Дано: день в паузе. Когда: день закончился. Тогда: статус «Пауза», не «Пропуск».
- **Ошибки:** нет (вычисляемый статус); сбой загрузки — `NETWORK_OFFLINE`.
- **Экран:** «Календарь» (C15); «Сегодня» (C07).
- **Связи:** BR-DATE-002, BR-DATE-005, BR-SAFETY-004, BR-LINK-005.

### FR-CAL-107 Перенос тренировки клиентом по правилам тренера [O5]

- **Предусловия:** тренировка запланирована на будущий день; тренер разрешил перенос в настройках клиента.

- **Связи:** BR-DATA-004, BR-DATE-001. Правила переноса: раздел 5, вопрос 10.

### FR-WORK-102 Отметка подхода: факт повторов и веса
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-3.
- **Предусловия:** экран выполнения открыт; подход не отмечен.
- **Описание:** клиент вводит фактические повторы (целое 0–999) и вес (0–1000 кг, шаг 0,5). Поля предзаполнены плановыми значениями. «Подход выполнен» отправляет подход на сервер с UUID. Статус подхода: «Сохраняется», затем «Сохранено» (после ответа сервера) или «Не отправлено».
- **Критерии приёмки:**
  - Позитивный: Дано: план 10 × 60 кг. Когда: клиент меняет на 8 × 62,5 и нажимает «Подход выполнен», сервер ответил 201. Тогда: статус «Сохранено», в факте 8 повторов и 62,5 кг.
  - Негативный: Дано: в поле повторов введено 1000. Когда: нажато «Подход выполнен». Тогда: под полем «Введите от 0 до 999», запрос не отправляется.
- **Ошибки:** `VALIDATION_FAILED` (422), `INVALID_TRANSITION` (тренировка уже завершена), `NETWORK_OFFLINE`, `NETWORK_TIMEOUT`, `INTERNAL`.
- **Экран:** «Выполнение тренировки» (C11).
- **Связи:** BR-SYNC-002, BR-SYNC-003, BR-DATA-001.

### FR-WORK-103 Таймер отдыха
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-3.
- **Предусловия:** подход сохранён.
- **Описание:** после сохранения подхода запускается обратный отсчёт отдыха из плана (по умолчанию 90 с, диапазон 5–600 с). По окончании — вибрация. «+15 с» добавляет время, «Пропустить» закрывает таймер. Таймер работает локально и не отправляет данных.
- **Критерии приёмки:**
  - Позитивный: Дано: отдых 90 с. Когда: подход сохранён. Тогда: отсчёт 90 → 0, по окончании вибрация, экран переходит к следующему подходу.
  - Негативный: Дано: таймер запущен, приложение свёрнуто на 30 с. Когда: клиент возвращается. Тогда: остаток показан с учётом прошедшего времени (около 60 с), таймер не сбрасывается.
- **Ошибки:** нет (локальный процесс).
- **Экран:** «Таймер отдыха» (C12).
- **Связи:** BR-SYNC-004 (таймер не записывает данных), BR-DATA-001.

### FR-WORK-104 Завершение тренировки и статус «Сохранено»
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-3.
- **Предусловия:** все подходы сохранены (статус «Сохранено»).
- **Описание:** «Завершить тренировку» отправляет запрос завершения с UUID тренировки и `Idempotency-Key`. Экран «Тренировка сохранена» показывается только после ответа 200. Итог (подходы, суммарный объём) формирует сервер.

  - Негативный: Дано: сети нет. Когда: клиент подтверждает удаление. Тогда: запись остаётся на экране, показано «Не удалено. Повторите».
- **Ошибки:** `NOT_FOUND` (запись не найдена), `NETWORK_OFFLINE`, `NETWORK_TIMEOUT`.
- **Экран:** «Вес и замеры: запись» (C22).
- **Связи:** BR-SYNC-002, BR-CONSENT-009, BR-DATA-008.

### FR-PROG-106 Личные рекорды [Should]

### 3.6. NOTIF: напоминания

### FR-NOTIF-101 Запрос разрешения на push и отказ
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-4. [O5]
- **Предусловия:** клиент включает напоминание.
- **Описание:** системное разрешение на push запрашивается при первом включении напоминания, а не при запуске. При отказе приложение работает: напоминания видны на «Сегодня» как баннер «Включить уведомления». Экран S12 объясняет, что push не придут, и даёт кнопку «Открыть настройки» телефона.
- **Критерии приёмки:**
  - Позитивный: Дано: разрешения нет. Когда: клиент включает напоминание и разрешает push. Тогда: напоминание сохранено на сервере, статус «Включено».
  - Негативный: Дано: система отказала в push. Когда: клиент включает напоминание. Тогда: статус «Уведомления выключены в настройках телефона», напоминание на сервере не создано, приложение не падает и не показывает «Включено».
- **Ошибки:** `PUSH_PERMISSION_DENIED` (клиентский код), `NETWORK_OFFLINE`.
- **Экран:** «Уведомления» (S11); «Уведомления выключены» (S12).
- **Связи:** BR-SAFETY-002.

### FR-NOTIF-102 Напоминание о тренировке: время и заранее [O5]
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-4. [O5]
- **Предусловия:** разрешение на push получено (FR-NOTIF-101); связь active; тренировка назначена.
- **Описание:** клиент задаёт локальное время напоминания (шаг 5 мин) и заранее: 0, 30, 60 или 120 мин. Напоминание приходит в день тренировки, если тренировка не выполнена. Текст нейтральный (FR-NOTIF-105).
- **Критерии приёмки:**
  - Позитивный: Дано: тренировка сегодня, напоминание 07:00 за 60 мин, часовой пояс `Europe/Berlin`. Когда: наступило 06:00 по Берлину. Тогда: push «Пора заниматься» доставлен.
  - Негативный: Дано: тренировка выполнена до 06:00. Когда: наступает время напоминания. Тогда: push не отправлен.
- **Ошибки:** `VALIDATION_FAILED` (время вне диапазона), `PUSH_PERMISSION_DENIED`, `NETWORK_OFFLINE`.
- **Экран:** «Напоминания» (C33).
- **Связи:** BR-DATE-001, BR-DATE-004, BR-SAFETY-002.

### FR-NOTIF-103 Напоминание о записи питания и замеров [Should]
- **Актор:** клиент.
- **Приоритет:** Should. **Этап:** EPIC-5.
- **Предусловия:** разрешение на push получено.
- **Описание:** отдельный переключатель, выключен по умолчанию. Один раз в день в выбранное время, если за день не введено ни одного итога и не внесён вес. Текст нейтральный, без упрёка.
- **Критерии приёмки:**
  - Позитивный: Дано: переключатель включён, итога за день нет. Когда: наступает время напоминания. Тогда: push «Не забудьте отметить день» доставлен.
  - Негативный: Дано: итог за день введён. Когда: наступает время напоминания. Тогда: push не отправлен.
- **Ошибки:** `PUSH_PERMISSION_DENIED`, `NETWORK_OFFLINE`.
- **Экран:** «Напоминания» (C33).
- **Связи:** BR-NUT-003, BR-SAFETY-002, BR-DATE-001.

### FR-NOTIF-104 Часовой пояс и переход на летнее время
- **Актор:** клиент, система.
- **Приоритет:** Must. **Этап:** EPIC-4.
- **Предусловия:** профиль с часовым поясом.
- **Описание:** если часовой пояс устройства отличается от профиля, приложение спрашивает «Перейти на [пояс]?». Без подтверждения пояс не меняется. После подтверждения сервер пересчитывает моменты напоминаний, даты календаря не сдвигаются. Переход на летнее и зимнее время сохраняет местное время напоминания (07:00 местного остаётся 07:00).
- **Критерии приёмки:**
  - Позитивный: Дано: напоминание 07:00 в `Europe/Berlin`, переход на летнее время 2027-03-28. Когда: наступает переход. Тогда: напоминание в 07:00 по Берлину, UTC-момент сдвинут на час.
  - Негативный: Дано: устройство в `Asia/Tokyo`, профиль `Europe/Berlin`. Когда: открыто приложение. Тогда: показан вопрос о смене пояса; без «Да» профиль не меняется, напоминания не пересчитываются.
- **Ошибки:** `VALIDATION_FAILED` (неверный пояс, 422), `NETWORK_OFFLINE`.
- **Экран:** «Часовой пояс» (S10); «Профиль» (C29).
- **Связи:** BR-DATE-003, BR-DATE-004, BR-DATE-001.

### FR-NOTIF-105 Нейтральный текст push без персональных данных
- **Актор:** система.
- **Приоритет:** Must. **Этап:** EPIC-4.
- **Предусловия:** push отправляется.
- **Описание:** заголовок и текст push берутся из фиксированного набора («Пора заниматься», «Не забудьте отметить тренировку»). В тексте нет имени, веса, питания, названия тренировки и имени тренера. Детали открываются в приложении после входа.
- **Критерии приёмки:**
  - Позитивный: Дано: напоминание о тренировке «Ноги». Когда: push отправлен. Тогда: текст из набора, без слова «Ноги».
  - Негативный: Дано: в запросе push передан идентификатор клиента или название упражнения. Когда: формируется payload. Тогда: сборка отклонена схемой, push не уходит.
- **Ошибки:** нет (внутренняя проверка схемы).
- **Экран:** нет (push).
- **Связи:** BR-SAFETY-002, BR-DATA-008. Серверная часть: FR-NOTIF-002.

### FR-NOTIF-106 Настройки уведомлений и их выключение
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-4.
- **Предусловия:** настройки открыты.
- **Описание:** один переключатель «Все напоминания» и отдельные переключатели для тренировки и (Should) записи питания. Изменение сохраняется на сервере после ответа; до ответа переключатель показывает прежнее значение.
- **Критерии приёмки:**
  - Позитивный: Дано: напоминание включено. Когда: клиент выключает «Все напоминания», сервер ответил 200. Тогда: напоминания не отправляются, статус «Выключены».
  - Негативный: Дано: сети нет. Когда: клиент выключает напоминание. Тогда: переключатель возвращается в «Включено», показано «Нет соединения. Не сохранено»; напоминание продолжает приходить.
- **Ошибки:** `NETWORK_OFFLINE`, `NETWORK_TIMEOUT`, `INTERNAL`.
- **Экран:** «Уведомления» (S11).
- **Связи:** BR-SYNC-002.

### FR-NOTIF-107 Снятие напоминаний при паузе, отвязке и закрытии связи
- **Актор:** система.
- **Приоритет:** Must. **Этап:** EPIC-4.
- **Предусловия:** связь переведена в paused, ended или заблокирована.
- **Описание:** при паузе напоминания о тренировках не отправляются. При отвязке, отзыве `coach_access` или блокировке все напоминания связи снимаются в той же транзакции, что и изменение связи. Клиент не получает push о тренировке тренера, связь которого закрыта.
- **Критерии приёмки:**
  - Позитивный: Дано: напоминание на завтра, клиент отвязался. Когда: завтра наступает время напоминания. Тогда: push не отправлен.
  - Негативный: Дано: связь paused. Когда: наступает время напоминания. Тогда: push не отправлен; экран не показывает ошибки.
- **Ошибки:** нет (внутренний процесс).
- **Экран:** нет (push); «Напоминания» (C33) показывает «Напоминания приостановлены».
- **Связи:** BR-LINK-009, BR-LINK-005, BR-SAFETY-004. Серверная часть: FR-NOTIF-003.

### 3.7. ACCT: профиль, экспорт, удаление

### FR-ACCT-101 Профиль: имя и часовой пояс
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-1.
- **Предусловия:** клиент аутентифицирован.
- **Описание:** профиль содержит имя (1–80 символов), видимое тренеру, и часовой пояс IANA. Часовой пояс обязателен. Устройство предлагает пояс, клиент подтверждает. Смена пояса не сдвигает даты календаря (FR-NOTIF-104).
- **Критерии приёмки:**
  - Позитивный: Дано: имя «Анна», пояс `Europe/Berlin`. Когда: нажато «Сохранить», сервер ответил 200. Тогда: профиль сохранён, тренер видит имя.
  - Негативный: Дано: имя пустое или пояс `Mars/Olympus`. Когда: нажато «Сохранить». Тогда: ошибка под полем (`VALIDATION_FAILED`), профиль не меняется.
- **Ошибки:** `VALIDATION_FAILED` (422), `NETWORK_OFFLINE`, `NETWORK_TIMEOUT`.
- **Экран:** «Профиль» (C29), «Имя и часовой пояс» (S10).
- **Связи:** BR-DATE-001, BR-DATE-003. Серверная часть: FR-ACCT-001.

### FR-ACCT-102 Экспорт данных
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-1 (запрос и статус), готовность файла — EPIC-4.
- **Предусловия:** клиент аутентифицирован; активного экспорта нет.
- **Описание:** клиент запрашивает экспорт всех своих данных (профиль, согласия, связи, тренировки и факт, питание, вес, замеры). Файл — JSON по контракту. Статус: «Готовим» → «Готово, скачать». Ссылка действует 24 ч. Одна активная выгрузка на клиента.
- **Критерии приёмки:**
  - Позитивный: Дано: активного экспорта нет. Когда: нажато «Запросить экспорт», сервер принял. Тогда: статус «Готовим»; по готовности «Скачать» открывает файл JSON, ссылка действует 24 ч.
  - Негативный: Дано: экспорт уже готовится. Когда: клиент нажимает «Запросить экспорт». Тогда: кнопка неактивна, текст «Экспорт уже готовится»; сервер отвечает `RATE_LIMITED` (429).
- **Ошибки:** `RATE_LIMITED` (429), `UNAUTHENTICATED` (401), `INTERNAL` (500), `NETWORK_OFFLINE`.
- **Экран:** «Мои данные» (S13).
- **Связи:** BR-DATA-007, BR-DATA-005. Серверная часть: FR-ACCT-002.

### FR-ACCT-103 Удаление аккаунта
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-1.
- **Предусловия:** клиент аутентифицирован.
- **Описание:** экран «Удалить аккаунт» показывает, что будет удалено (профиль, тренировки, вес, замеры, питание, согласия) и что удаление необратимо. Удаление требует двух шагов: кнопка «Удалить» и подтверждение. У клиента со связью связь завершается и тренер теряет доступ. Вход после удаления невозможен. Полное удаление данных (включая бэкапы по ротации и Sentry) выполняется не позже 1 месяца (BR-DATA-006).
- **Критерии приёмки:**
  - Позитивный: Дано: клиент подтвердил удаление, сеть есть. Когда: сервер ответил 204. Тогда: вход невозможен, тренер потерял доступ, открыт экран входа (S03) с текстом «Аккаунт удалён».
  - Негативный: Дано: клиент нажал «Удалить» и отменил в диалоге. Когда: диалог закрыт. Тогда: аккаунт активен, данные не изменены.
- **Ошибки:** `VALIDATION_FAILED` (нет второго шага, 422), `UNAUTHENTICATED`, `VERSION_CONFLICT`, `NETWORK_OFFLINE`, `NETWORK_TIMEOUT`.
- **Экран:** «Удаление аккаунта» (S14).
- **Связи:** BR-DATA-006, BR-LINK-009, BR-LINK-010. Серверная часть: FR-ACCT-003.

### FR-ACCT-104 Выход из аккаунта
- **Актор:** клиент.
- **Приоритет:** Must. **Этап:** EPIC-1.
- **Предусловия:** клиент вошёл.
- **Описание:** выход удаляет токены из защищённого хранилища устройства и локальные данные экранов. Сервер отзывает сессию, если есть сеть. Несохранённые подходы и введённые значения теряются, клиент получает предупреждение до выхода.
- **Критерии приёмки:**
  - Позитивный: Дано: клиент вошёл, нет несохранённых данных. Когда: нажато «Выйти» и подтверждено. Тогда: токены удалены, открыт экран входа (S03).
  - Негативный: Дано: сети нет. Когда: клиент выходит. Тогда: токены на устройстве удалены, выход выполнен; отзыв сессии на сервере повторяется при следующем запуске с сетью.
- **Ошибки:** `UNAUTHENTICATED` (при отзыве сессии ответ игнорируется), `NETWORK_OFFLINE`.
- **Экран:** «Профиль» (C29); «Вход» (S03).
- **Связи:** BR-SYNC-004.

## 5. Допущения и вопросы

Допущения приняты для draft, их нужно подтвердить. Вопросы блокируют либо меняют требования.

1. **Соответствие EPIC и этапов.** Принято: EPIC-N = этап N для N = 1…4; EPIC-5 = этап 6; EPIC-6 = этап 7. Этап 5 (бета) новых клиентских требований не добавляет. Подтвердить с `00-validation.md` и `01-conventions.md` (там EPIC-0…EPIC-7).
2. **Серверная часть не дублируется.** Логика правил (AccessPolicy, погашение, каскады, экспорт, удаление) — в `12-fr-shared-admin.md` (FR-LINK-001…012, FR-ACCT-001…006, FR-NOTIF-001…004). Здесь описаны экраны и поведение клиента. Ссылки «Серверная часть» указывают на соответствующие серверные требования.
3. **Код ошибки для негативных состояний инвайта (вопрос).** `13-business-rules.md` (BR-INVITE-006) и `12-fr-shared-admin.md` (FR-LINK-004) с `01-conventions.md` (раздел 2, п. «Чужой ресурс и негативные состояния инвайта») расходятся: `INVITE_INVALID` против `NOT_FOUND`. В этом файле принят `INVITE_INVALID` по BR-INVITE-006. Нужна унификация перед контрактом.
4. **Возрастной гейт — BR-правило отсутствует (вопрос).** В `13-business-rules.md` нет правила для возраста: `BR-GATE-*` описывает метрики беты. Гейт описан в FR-ACCT-005 (EPIC-4). В этом файле экран нужен в EPIC-1 (регистрация). Предлагается: (а) добавить BR возраста в `13-business-rules.md`, (б) согласовать EPIC: экран в EPIC-1, юридическое подписание ToS в EPIC-4.
5. **Напоминания клиенту: Must или Should (вопрос, противоречие).** По O5 (`00-validation.md`, `13-business-rules.md`) напоминания клиенту — Must в бете. `12-fr-shared-admin.md` (FR-NOTIF-004) — Should, EPIC-6, а план §3 относит напоминания к этапу 6. В этом файле: FR-NOTIF-102 — Must, EPIC-4 [O5]. FR-NOTIF-004 в `12` нужно обновить либо подтвердить решение.
6. **Пауза и возобновление (вопрос).** BR-LINK-006 делает resume действием тренера. Клиент только просит паузу (FR-LINK-116) и не возобновляет её сам (FR-LINK-118). Если владелец хочет кнопку «Возобновить» у клиента, правило BR-LINK-006 и `link.ts` меняются (K6).
7. **Смена тренера (допущение).** Замены одним шагом нет: связь клиента может быть одна (BR-LINK-002, FR-LINK-007), поэтому сначала отвязка, затем новый инвайт (FR-LINK-120). Подтвердить: это соответствует ответу O2.
8. **Отзыв `coach_access` завершает связь; отзыв `health_data` — нет (подтверждено каталогом).** Соответствует BR-CONSENT-006 и FR-LINK-010. Экран «Согласия» различает эти два отзыва (FR-LINK-113 и FR-LINK-114).
9. **Порог калорий (блокер для FR-NUT-103).** Значение порога не задано и утверждается специалистом (BR-NUT-001, BR-SAFETY-003). До утверждения функция выключена. Числа в примерах (1200 ккал) — только иллюстрация.
10. **Правила переноса клиентом [O5] (вопрос).** Правила (окно, лимит переносов) не описаны в каталоге BR. Допущение, пока тренер не задал иное: перенос в пределах той же календарной недели, не более одного переноса в неделю. Нужен ответ владельца (Should, EPIC-5).
11. **Отметка выполнения задним числом — не в MVP (допущение).** Пропуск фиксируется сервером по окончании дня (BR-DATE-002), а отметка задним числом не предусмотрена. Если нужна, нужен срок (например, 48 ч) и решение по BR-DATA-001.
12. **Таймаут 15 с (допущение).** Ни CLAUDE.md, ни BR не задают числа. Таймаут ожидания ответа на отправку — 15 с, после чего статус «Не отправлено».
13. **Несохранённые данные при закрытии приложения (вопрос UX).** Офлайн-очередь вне MVP (BR-SYNC-004, Later в плане §2.2). Значит, неотправленные подходы и значения теряются при закрытии приложения; клиент получает предупреждение (FR-ACCT-104). Подтвердить с UX.
14. **Кэш плана при отсутствии сети (допущение).** Последняя полученная версия плана показывается только для чтения с меткой «Нет связи, версия N». Факт, отметки и итоги из кэша не показываются (BR-SYNC-004). Подтвердить: это отступает от S17 (сплошная ошибка) только для плана.
15. **Экспорт и удаление (допущение).** Экспорт: JSON, ссылка 24 ч (BR-DATA-005, FR-ACCT-002), одна активная выгрузка (код 429 — допущение). Удаление: без периода отмены по FR-ACCT-003, полный срок ≤1 месяца (BR-DATA-006). Юридически нужен ли период отмены — вопрос DPO.
16. **Тренер после отвязки (вопрос DPO).** BR-LINK-010 описывает только клиента: история у клиента, тренер теряет доступ. Что тренер сохраняет у себя (заметки, комментарии), не определено. Блокер для текста экрана FR-LINK-119.
17. **Страница-посадка по ссылке (вопрос).** Для ссылки без установленного приложения нужна веб-страница вне мобильного кабинета. Не покрыта ADR. Требование FR-LINK-103 описывает поведение, но не реализацию.
18. **Вход через провайдера.** Sign in with Apple обязателен при социальном входе (CLAUDE.md §3). Состав провайдеров (email, Google) и детали входа — в FR-AUTH-001 (`12-fr-shared-admin.md`). Здесь вход описан как шаг FR-LINK-106.
19. **Замеры: фиксированный список (допущение).** В MVP четыре замера: талия, грудь, бёдра, бицепс. Настраиваемый список тренером — Later, не описан.
20. **Границы ввода (допущения).** Повторы 0–999; вес подхода 0–1000 кг, шаг 0,5; вес тела 20,0–400,0 кг; замеры 10,0–250,0 см; калории 0–10000; макросы 0–1000 г. Значения нужно сверить с тренерами и с `packages/contracts`.
21. **Таймер отдыха (допущение).** По умолчанию 90 с, диапазон 5–600 с. План тренера может задать своё значение.
22. **Дневник еды (вопрос).** BR-NUT-004 относит дневник еды к Should, а план §1 исключает базу продуктов из MVP. Здесь FR-NUT-106 отнесён к Later, а ручной ввод итогов (FR-NUT-102) — к Must. Подтвердить.
