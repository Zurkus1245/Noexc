## 4. Пробелы в требованиях (добавить в систему требований)
**Безопасность/GDPR:** отзыв согласия как событие с каскадом; реестр полей ст. 9; отдельные согласия (сбор, передача тренеру, питание); возрастной гейт 18+ (самодекларация); инвайт ≥128 бит, хранение хэша, единый 404 на любое негативное состояние, атомарное погашение, rate-limit; MFA тренера; роли GDPR (тренер — контролёр, платформа — процессор) и DPA; сроки хранения; уведомление об инциденте ≤72 ч; экспорт/удаление в ≤1 мес с каскадом (бэкапы, Sentry, push-токены); восстановление аккаунта; доступ админа к здоровью только по тикету с временным грантом; push без PII; аналитика только EU и без данных здоровья; порог ккал как именованная константа, утверждает специалист.
**UX (22 пункта в отчёте ревьюера, ниже сгруппированы в 19 строк):** клиент без инвайта; страница-посадка и ручной ввод кода; истёкший/использованный/отозванный инвайт; отказ от согласий; повторный запрос согласия; онбординг тренера; пустые состояния; «тренер ещё не назначил»; офлайн на каждом экране; отвязка/смена тренера/удаление тренера; пауза; экспорт; перенос клиентом; «у клиента не обновлено»; предупреждение по ккал; отказ в push; блокировка админом; один человек — тренер и клиент; планшет.
**NFR:** доступность (WCAG 2.2 AA, не только цветом), локализация, производительность, версии ОС, размеры, лимиты, RPO/RTO.
**Продукт:** замер выигрыша тренера (минуты на правку плана до/во время беты); метрика клиента; экран «кому нужна реакция сегодня»; напоминания клиенту; импорт клиентов; комментарий к тренировке.

## 5. Реалистичность (оценка скептика, не проверена декомпозицией)
Бета 12–17 нед маловероятна; реалистично 20–28 нед. Юрлицо/страна блокируют аккаунты Apple/Google; Google Play для личного аккаунта требует закрытого теста (проверить правила на дату); DPIA/DPA до первых реальных данных; ревью сторов по данным здоровья.

## 6. Открытые решения владельца (блокируют часть требований)
| ID | Вопрос | Рекомендация оркестратора |
|---|---|---|
| O1 | Один аккаунт = одна роль? | Да в MVP; тренер, который тренируется сам, заводит второй аккаунт |
| O2 | Может ли у клиента быть два тренера? | Нет: одна `active|paused` связь на клиента |
| O3 | Пауза закрывает доступ тренера к данным? | Нет, только отключает напоминания и «пропуски»; клиент запрашивает, тренер подтверждает; нужна правка `link.ts` |
| O4 | Админка «к бете»: веб или runbook+скрипты? | Admin-lite (отзыв связи, экспорт/удаление, аудит) до беты, полная веб-админка к запуску |
| O5 | В Must беты: экран «кому нужна реакция», напоминания клиенту, импорт CSV, комментарий к тренировке? | Да для первых трёх; комментарий — Should. Скептик предлагает вырезать — решает основатель |
| O6 | Питание в бете: КБЖУ или одно поле «ккал/день»? | КБЖУ по плану, но дневник еды клиента — Should |
| O7 | Страна, язык, юрлицо | Блокирует сторы и юр-пакет; без решения язык один, строки в словаре |
| O8 | Тренеры — онлайн или офлайн/гибрид? | Только онлайн-тренеры с 10+ клиентами |

Требования ниже пишутся по рекомендациям оркестратора; всё, что зависит от O1–O8, помечено тегом `[O#]` и меняется одним правилом после решения владельца.
