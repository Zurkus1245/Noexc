# 13. Бизнес-правила

Дата: 2026-11-23. Каталог проверяемых правил, на которые ссылаются FR в `12-fr-shared-admin.md`. Одно правило в строке. Тип проверки: unit (домен, `packages/domain`), contract (`packages/contracts`), integration (API + Postgres через Testcontainers), e2e (Maestro), job (worker), ops (процедура, регламент), review (ручная проверка документа). Решения O1–O8 учтены как рекомендованные (`00-validation.md`, раздел 6); пометка [O#] означает зависимость от решения.

## 1. Связь (BR-LINK)

| ID | Правило | Обоснование | Источник | Проверка |
|---|---|---|---|---|
| BR-LINK-001 | Связь тренер–клиент создаётся только погашением валидного инвайта; один инвайт порождает не более одной связи. | Связь — единственный источник права доступа к данным клиента. | CLAUDE §5 (AccessPolicy); план §3 этап 1 | integration |
| BR-LINK-002 | У клиента не более одной связи в статусе active или paused. Гарантируется ограничением БД, не только кодом. [O2] | Данные клиента не должны попадать к двум тренерам. | `00-validation` O2; `schema.prisma` (CoachClient, комментарий о миграции) | integration (SQL-ограничение) + unit |
| BR-LINK-003 | Тренер получает доступ к данным клиента только при одновременном выполнении: связь с этим тренером и этим клиентом, статус не ended, действующее согласие `coach_access`; для данных здоровья — дополнительно `health_data`. | Изоляция данных между тренерами и клиентами. | CLAUDE §5, §9; план §5; `domain/access-policy.ts` | unit + integration (IDOR-тесты) |
| BR-LINK-004 | Неизвестный или неподдерживаемый статус связи трактуется как закрытый доступ (fail-closed). | Новый статус в будущем не должен открыть доступ. | CLAUDE §9 (least privilege); К2 | unit (`isLinkOpen`, значение `unknown`) |
| BR-LINK-005 | Пауза связи не закрывает доступ тренера к данным клиента; пауза отключает напоминания и учёт пропусков. [O3] | Клиент просит паузу по болезни; тренер продолжает видеть план и результаты. | `00-validation` O3; план §2.2 («пауза/болезнь тренеру») | unit (`transitionLink`, `decideClientAccess` при paused) + integration |
| BR-LINK-006 | Допустимые переходы: pause и resume — тренер; end — тренер, клиент или администратор. Прочие переходы отклоняются с INVALID_TRANSITION. | Разделение ролей; администратор должен иметь право отзыва (Must). | `domain/link.ts` (`LINK_TRANSITIONS`); план §2.1 (пауза/отвязка); К4, К6 | unit (матрица акторов и статусов) |
| BR-LINK-007 | Отвязка (end) закрывает доступ немедленно: следующий запрос тренера к данным клиента получает 404 без задержки кэша. | Клиент должен быть уверен, что тренер больше не видит данные. | план §5; план §3 этап 1 («отвязка мгновенно закрывает доступ») | integration (запрос сразу после end) |
| BR-LINK-008 | Статус ended необратим. Возобновление общения — только новым инвайтом и новой связью. | История связи не переписывается; старые согласия не переходят на новую связь. | план §5; `domain/link.ts`; `schema.prisma` (endedAt, endedBy) | unit + integration |
| BR-LINK-009 | При отвязке (end, отзыв администратором, отзыв `coach_access`, удаление тренера) в одной транзакции удаляются будущие записи календаря и отменяются запланированные напоминания этой связи. | Тренировки не должны появляться после отвязки; напоминания не должны уходить. | план §5 (отвязка); К8 | integration (проверка CalendarEntry и pg-boss-задач) + job |
| BR-LINK-010 | После отвязки история (факт, версии плана, согласия) остаётся у клиента; тренер теряет доступ к ней. | Клиент владеет своими данными; тренер не сохраняет доступ к истории. | план §5 («история остаётся у клиента»); CLAUDE §9 | integration |
| BR-LINK-011 | При удалении аккаунта тренера его связи переходят в ended (endedBy=coach), клиент видит связь без имени тренера; связь не удаляется. | Клиент сохраняет историю; ссылка на удалённого пользователя обнуляется. | `schema.prisma` (CoachClient: onDelete SetNull, комментарий); `contracts/coaching.ts` | integration |

## 2. Инвайт (BR-INVITE)

| ID | Правило | Обоснование | Источник | Проверка |
|---|---|---|---|---|
| BR-INVITE-001 | Код инвайта — не менее 128 бит энтропии от криптографически стойкого генератора, формат 26 символов Crockford base32. | Перебор кода должен быть невозможен при rate-limit. | CLAUDE §9 (invite codes: high entropy); `contracts/invite.ts` (INVITE_CODE_LENGTH) | unit (длина, алфавит, источник случайности) |
| BR-INVITE-002 | В БД хранится только хэш SHA-256 кода; сам код не хранится и не возвращается после создания. | Утечка БД не раскрывает действующие коды. | `schema.prisma` (Invite.codeHash); `contracts/export.ts` (коды не экспортируются) | integration (в таблице нет открытого кода) + review |
| BR-INVITE-003 | Срок действия инвайта — 168 часов от создания; после срока код недействителен. | Ограничение времени жизни кода. | `contracts/invite.ts` (INVITE_TTL_HOURS = 168); `domain/invite.ts` | unit (граница `now == expiresAt` → expired) |
| BR-INVITE-004 | Инвайт одноразовый: успешное погашение помечает его использованным (usedAt), повторное погашение невозможно. | Один код — одна связь. | `domain/invite.ts`; `schema.prisma` (usedAt) | unit + integration |
| BR-INVITE-005 | Приоритет состояний инвайта: revoked, затем used, затем expired, затем valid. | Явный факт (отзыв, использование) важнее пассивного срока. | `domain/invite.ts` (`inviteState`) | unit (все комбинации фактов) |
| BR-INVITE-006 | Любое негативное состояние (несуществующий, истёкший, использованный, отозванный, чужой код) возвращает идентичный ответ 404 с кодом INVITE_INVALID. | Нет утечки состояний и существования кода. | план §1 (раздел 3 этап 1: «чужой ресурс отдаёт 404»); CLAUDE §6; FR-LINK-004 | contract (сравнение тел ответов) + integration |
| BR-INVITE-007 | Погашение атомарно: одна условная операция «не использован, не отозван, не истёк», при параллельных запросах успешен ровно один. | Защита от гонки и двойной связи. | `schema.prisma`; риск безопасности (консилиум 1, раздел 4) | integration (параллельные запросы, Testcontainers) |
| BR-INVITE-008 | Тренер создаёт не более 5 инвайтов в час. Превышение возвращает 429 RATE_LIMITED. | Защита от массового приглашения и спама. | FR-LINK-002; `contracts/rate-limits.ts` сейчас задаёт 10 (расхождение, см. раздел 13 ниже) | integration + unit (окно) |
| BR-INVITE-009 | Погашение: не более 5 попыток за 10 минут отдельно по IP и по значению кода; превышение даёт 429 даже при верном коде. | Защита от перебора кодов. | `contracts/rate-limits.ts` (redeemAttempt); CLAUDE §9 | integration (счётчик в Postgres, два инстанса) |
